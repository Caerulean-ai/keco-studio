# 🔧 缓存更新问题修复

## 📋 问题描述

### 问题 1: 创建项目后 Sidebar 不更新
**症状**: 创建项目后，右边显示已创建，但左边 Sidebar 没有刷新，需要手动刷新页面才能看到新项目

**原因**: 
- 使用了 `queryClient.invalidateQueries()` 只是标记查询为"过期"
- 但不会立即触发重新获取数据
- 由于配置了 `refetchOnMount: false`，组件不会自动重新获取

### 问题 2: 用户切换后看到旧数据
**症状**: 退出登录并注册新用户后，看到的还是上一个用户的项目数据，需要手动刷新才会消失

**原因**:
- 用户登出时，React Query 的缓存没有被清除
- `globalRequestCache` 中的权限验证缓存也没有被清除
- 新用户登录时，由于缓存还在，会显示旧数据

---

## ✅ 解决方案

### 修复 1: 使用 `refetchQueries` 替代 `invalidateQueries`

**修改文件**: `src/components/layout/Sidebar.tsx`

**改动说明**:
将所有 `queryClient.invalidateQueries()` 替换为 `queryClient.refetchQueries()`

```typescript
// ❌ 之前：只标记为过期，不立即获取
queryClient.invalidateQueries({ queryKey: ['projects'] });

// ✅ 现在：立即重新获取数据
queryClient.refetchQueries({ queryKey: ['projects'] });
```

**影响的场景**:
1. ✅ 创建项目后
2. ✅ 删除项目后
3. ✅ 创建/删除库后
4. ✅ 创建/删除文件夹后

---

### 修复 2: 用户切换时清除所有缓存

#### 2.1 创建全局 QueryClient 访问器

**修改文件**: `src/lib/providers/QueryProvider.tsx`

```typescript
// 创建全局 QueryClient 实例引用
let globalQueryClientInstance: QueryClient | null = null;

export function getGlobalQueryClient(): QueryClient | null {
  return globalQueryClientInstance;
}
```

**作用**: 允许在任何地方访问 QueryClient 实例，不仅限于 React 组件

#### 2.2 在 AuthContext 中清除缓存

**修改文件**: `src/lib/contexts/AuthContext.tsx`

**场景 1: 用户登出**

```typescript
const signOut = useCallback(async () => {
  try {
    await supabase.auth.signOut();
    
    // 1. 清除 React Query 缓存
    const { getGlobalQueryClient } = await import('@/lib/providers/QueryProvider');
    const queryClient = getGlobalQueryClient();
    if (queryClient) {
      queryClient.clear();
    }
    
    // 2. 清除全局请求缓存（权限验证等）
    const { globalRequestCache } = await import('@/lib/hooks/useRequestCache');
    globalRequestCache.invalidate();
  } catch (e) {
    console.error('Logout failed', e);
  }
}, [supabase]);
```

**场景 2: 用户切换**

```typescript
const { data: { subscription } } = supabase.auth.onAuthStateChange(async (event, session) => {
  if (session?.user) {
    // 检测用户是否切换
    const previousUserId = currentUserId.current;
    const newUserId = session.user.id;
    
    if (previousUserId && previousUserId !== newUserId) {
      // 用户已切换 - 清除所有缓存
      const { getGlobalQueryClient } = await import('@/lib/providers/QueryProvider');
      const queryClient = getGlobalQueryClient();
      if (queryClient) {
        queryClient.clear();
      }
      
      const { globalRequestCache } = await import('@/lib/hooks/useRequestCache');
      globalRequestCache.invalidate();
    }
    
    // ... 继续加载新用户数据
  } else {
    // 用户登出 - 清除所有缓存
    // ... 清除逻辑
  }
});
```

#### 2.3 更新 Sidebar 使用 AuthContext 的 signOut

**修改文件**: `src/components/layout/Sidebar.tsx`

```typescript
// ❌ 之前：直接调用 supabase.auth.signOut()
```

## 📊 技术细节

### `invalidateQueries` vs `refetchQueries`

| 方法 | 行为 | 适用场景 |
|------|------|---------|
| `invalidateQueries` | 标记为过期，等待下次访问时才获取 | 后台数据更新 |
| `refetchQueries` | 立即重新获取数据 | 需要立即显示更新 ✅ |

### 缓存清理策略

**两层缓存系统**:

1. **React Query 缓存**
   - 缓存业务数据（projects, libraries, folders）
   - 使用 `queryClient.clear()` 清除

2. **globalRequestCache**
   - 缓存权限验证结果
   - 缓存常用查询（避免重复请求）
   - 使用 `globalRequestCache.invalidate()` 清除

**清除时机**:
- ✅ 用户登出
- ✅ 用户切换
- ✅ 会话过期

## ⚠️ 注意事项

1. **性能影响**
   - `refetchQueries` 会立即发起网络请求
   - 但由于使用了请求去重，不会导致重复请求

2. **缓存清理**
   - `queryClient.clear()` 会清除所有 React Query 缓存
   - `globalRequestCache.invalidate()` 会清除所有自定义缓存
   - 这是必要的，以确保用户切换时数据隔离

3. **向后兼容**
   - 所有修改都是增强现有功能
   - 不影响其他功能的正常运行
